# 홈 뒤로가기 종료 처리 수정

## 요청 및 원인

여러 화면을 이용한 뒤 홈으로 돌아와 뒤로가기를 누르면, 앱에서 나가기까지 여러 번 뒤로가야 한다는 재신고를 확인했다.

기존 코드는 홈에서 종료를 확인한 뒤 `history.back()`을 한 번 호출했다. 홈 메뉴의 `replace`도 마지막 기록만 대체하므로, 코스·커뮤니티 등 이전에 방문한 화면 기록은 남아 있었다. 기존 테스트는 실제 기록 위치를 이동시키지 않아 이 문제를 검증하지 못했다.

## 수정한 동작

- 홈의 첫 뒤로가기에서 종료 확인을 요청한다. 취소하면 홈의 종료 가드를 복원한다.
- 챗봇이나 장소 상세 창이 열려 있으면 해당 창을 먼저 닫는다.
- 종료를 확인하면 창 닫기를 요청한다. 브라우저가 허용하지 않으면 Navigation API로 현재 문서에서 쌓인 이동 기록의 시작 위치로 돌아간다.
- 이전 화면이 렌더링되지 않도록 목표 기록의 `popstate`를 먼저 처리하고, 현재 홈 URL과 Next 라우터 상태를 보존한다.
- 웹에서 닫히지 않은 경우 추가 뒤로가기를 안내한다. ‘계속 이용하기’를 선택하면 종료 가드를 다시 활성화한다.
- 이전 문서로 넘어가는 탐색은 강제로 가로채지 않는다. Navigation API가 없는 브라우저는 기존 뒤로가기 동작을 유지한다.

변경 파일: `src/lib/navigation/homeBackExit.ts`, `src/lib/navigation/homeBackExit.test.ts`, `src/components/HomeBackExitGuard.tsx`.

## 최초 로컬 검증 시점의 적용 상태와 남은 확인

코드는 로컬 작업 공간에 반영했다. 커밋, 원격 브랜치 병합, 운영 배포 및 APK 배포는 수행하지 않았다.

연결된 Android 기기가 없어 TWA의 실제 종료는 검증하지 못했다. **이 항목을 운영 앱에서 해결 완료로 표시하려면 배포 후 실기기 확인이 필요하다.** 특히 새로고침·로그인·외부 문서 이동 전의 기록이 남은 경우에는 추가 뒤로가기 한 번만으로 종료된다고 보장할 수 없다. 이번 변경은 현재 문서의 앱 내부 이동 기록을 건너뛰는 웹 수정이며, Android 네이티브 종료 연동을 추가한 작업은 아니다.

실기기 확인 경로: 앱 실행 → 코스 → 코스 상세 → 커뮤니티 → 홈 → 뒤로가기 → 취소 → 뒤로가기 → 확인. 취소 시 홈이 유지되는지, 확인 뒤 이전 코스·커뮤니티가 다시 나타나지 않는지, 안내 후 물리 뒤로가기에서 앱을 벗어나는지 확인한다. 앱 바로가기로 코스에 진입한 경우와 로그인·새로고침 후에도 반복한다.

브라우저 제약 근거: [Window.close](https://developer.mozilla.org/en-US/docs/Web/API/Window/close), [Chrome Navigation API](https://developer.chrome.com/docs/web-platform/navigation-api).
